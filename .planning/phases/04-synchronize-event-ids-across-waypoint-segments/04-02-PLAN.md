<threat_model>
### Assets
- Annotation integrity: one event type change must update only its Event Waypoint, including legacy-imported records.
- Display integrity: each Event Waypoint list row must show the type belonging to that marker.
- History integrity: one user action remains one reversible history entry.

### Trust Boundaries
- Imported JSON can contain EventInstanceId on boxes but omit it from the corresponding marker.
- Event waypoint frame ranges can overlap while retaining different segment identities.

### Threats
- T-04-04 (high): Falling back from a box instance ID to range-only matching can mutate a second overlapping segment.
- T-04-05 (medium): A range-only list lookup can display another segment's stale event type after a valid update.
- T-04-06 (medium): Marker backfill can overwrite a non-empty segment identity or create a second undo action.

### Mitigations
- Use exact instance identity first; permit mixed metadata only for one blank marker matching the selected prior EventId, otherwise make no change.
- Resolve list boxes with `TrackingIdentityHelper.MatchesWaypoint`, frame bounds, and `!IsDeleted`.
- Backfill only a blank marker EventInstanceId, update its ObjectId only after a successful mutation, and retain the existing grouped box history action.
</threat_model>
