updates every active event box in that same Event Waypoint, safely preserves
identity and history, and immediately refreshes the affected UI.

allowing identical event types in different event segments to bleed together.
Output: A reusable event-waypoint resolver, atomic grouped undo/redo support,
combo-box integration, and executable regression coverage for `EVT-06`.

<threat_model>
### Assets
- Annotation integrity: an EventId change must not alter an unrelated event segment or deleted history.
- Undo integrity: a single user action must have a complete reversible history.

### Trust Boundaries
- Imported legacy JSON may omit `EventInstanceId`.
- UI selection supplies a selected box that can be inside overlapping waypoint frame ranges.

### Threats
- T-04-01 (high): Matching by EventId or rectangle can mutate another event waypoint that shares a type.
- T-04-02 (medium): Undo lookup by changed EventId can restore only part of a grouped update or the wrong box.
- T-04-03 (medium): Soft-deleted boxes can be revived semantically by changing their historical EventId.

### Mitigations
- Prefer exact `EventInstanceId`; legacy fallback is limited to selected waypoint bounds plus original EventId and fails closed when ambiguous.
- Store grouped before/after states or stable box references for undo/redo rather than resolving by post-change identity.
- Filter `IsDeleted` boxes before any event type mutation and cover all three cases in the harness.
</threat_model>
