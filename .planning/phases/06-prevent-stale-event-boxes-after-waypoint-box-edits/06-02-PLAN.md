<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Helper mutation plan → `boundingBoxes` | Only a validated, identity-scoped plan may mutate in-memory annotations. |
| Event edit → undo/redo history | Multiple existing and created boxes must reverse together, without resolving by a mutable identity. |
| Event deletion UI → persisted annotation state | Frame-local deletion must preserve its tombstone and cannot become a waypoint deletion. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | `PropagateEventBoxFromCurrentFrame` | mitigate | Apply only the non-empty Plan 01 result, whose first operation is fail-closed `ResolveActiveScope`; never reintroduce EventId-only target filters. |
| T-06-02 | Tampering | Propagation apply/undo/redo | mitigate | Preserve `IsDeleted` targets as untouched tombstones and exclude them from added-box decisions; grouped history never restores a deleted frame by creating a box. |
| T-06-03 | Tampering | Grouped rectangle undo | mitigate | Store stable references and before/after rectangles plus created box references in one dedicated action; do not locate a box by mutable EventId. |
| T-06-04 | Integrity | `btnDeleteLabel_Click` | mitigate | Retain frame-local tombstone behavior and bypass `RecordDisappearanceIntent`; leave full-range removal exclusively in existing waypoint deletion. |
| T-06-SC | Tampering | Package installs | accept | No dependency installation occurs in this plan. |
