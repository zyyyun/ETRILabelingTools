<threat_model>
### Assets
- Parent annotation integrity: body boxes and person/vehicle waypoint markers must survive every child delete.
- Child identity integrity: a deletion must not cross from one person's face or one vehicle's plate to another.
- JSON referential integrity: saved child links cannot point to a deleted child annotation.
- Labeling continuity: `G` must not remove later-frame child boxes through a disappearance side effect.

### Trust Boundaries
- Imported data can rely on `LinkedPersonId`/`LinkedVehicleInstanceId` and may contain overlapping parent waypoint ranges.
- The generic shortcut code currently treats all selected boxes alike and records disappearance intent.

### Threats
- T-08-01 (high): Label-only person/vehicle matching removes a body or another object's child boxes.
- T-08-02 (high): The generic disappearance record turns a current-frame `G` action into a multi-frame child removal.
- T-08-03 (medium): Removing child links or annotations also removes the linked body annotation.
- T-08-04 (medium): An unresolved parent waypoint causes a broad fallback deletion.

### Mitigations
- Require child subtype, linked identity, and inclusive parent-waypoint range in one fail-closed helper.
- Bypass `RecordDisappearanceIntent` only for Phase 8 child paths; retain it for existing body behavior.
- Keep soft-delete semantics and rely on existing active-box JSON grouping to regenerate only valid child links.
- Show a message and make no mutation if the helper cannot resolve exactly one parent waypoint.
</threat_model>
